# コード・計画の独立レビュー

差分または計画のレビューを依頼されたときに読む。入力は対象の差分・計画と、明示された前提。成果物は判断に使える指摘であり、修正コードではない。

## 観点

1. セキュリティ・悪用経路：公開 GAS エンドポイントへの直接呼び出し、AI 費用の消費、大量登録・通知、入力検証の抜け、数式注入、秘密情報の露出、CSP・ヘッダーの緩和
2. 正しさ・回帰：保存の重複防止（送信ID）、回答の完全性、リセット時の古い応答、現在の公開版（docs/RELEASE.md の「現在の公開版」の表）との互換性
3. 障害時の挙動：タイムアウト、不正な応答、ロック競合、設定不足のときに安全側へ倒れるか
4. テストの不足：変更した挙動を `test/` が実際に確かめているか
5. 計画の場合：計画と現在のコードの食い違い、隠れた前提、手順の抜け（反映順・ロールバック）

文体、命名の好み、全面的な書き換えの提案は扱わない。

## 出力

重大度の高い順に、重大な指摘がなければ「重大な指摘なし」と返す。各指摘に次を書く。

- 重大度：P1（反映前に必須）／P2（続けて修正）／P3（任意）
- 場所：`file:line`
- 内容：何が問題か（1〜2文）
- 失敗シナリオ：どの入力・状態で、何が起きるか
- 根拠の確かさ：確認済み（コード・テストで確かめた）／未確認／推論 を区別する

最後に、反映判断を `そのまま進める／条件付きで進める／一度止める` のいずれかで返し、理由を1〜2文で書く。

指摘を自動でコードへ反映しない。採否は人間が判断する。
