ソースの同期だけを行う場合は、本番を変えないための扱いを先に確定します。自動ビルドの設定変更や本番配備は、対象と影響について承認された範囲で行います。GASの権限・プロパティやGit接続を変更する必要はありません。

## 今後の変更

1. mainから作業ブランチを作り、対象の変更を実装する。
2. `npm ci`、`npm test`、本番向けビルドを確認する。テストでは実サービスに保存・通知・AI生成をしない。
3. 差分を確認してGitへコミットし、GitHubで管理する。push前にCloudflareの自動配備条件を確認する。
4. 本番反映の対象・差分・未確認事項を確定し、承認済みの範囲で配備する。
5. GASを変更する場合は、フロントとの互換性を検証する。保存v2はGASのバージョン16以降が必要なため、今回と同じ構成ではGASを先に配備する。
6. 反映後、HTML・JS・CSSとGASの公開バージョンを確認し、`releases/`に記録する。
7. 対応するコミットに新しい公開版タグを付ける。既存の公開版タグは移動させない。

公開記録には、配備日時、Gitタグ、Workerバージョン、GASバージョン、静的アセットのハッシュ、復元先、実施した検証と未確認事項を含めます。秘密情報や診断回答者の情報は記録しません。

## 復元の注意

本番の復元も本番操作です。GitのcheckoutだけではCloudflareやGASは切り替わりません。

画面だけを以前のWorkerバージョンへ戻す場合、GAS16は旧`save_only`にも対応しています。GASも15へ戻す場合は、保存v2を使う画面との不整合を避けるため、画面を先に戻します。既存の回答や送信ID列は削除しません。

`test/fixtures/Code.v15.gs`は互換性テスト用で、運用上の復元を自動実行するファイルではありません。
