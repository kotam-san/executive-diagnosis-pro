# AIコーチ高速化とモデル更新の計画（2026-10-26）

## 目的

- AIコーチ（分析・アクションプラン）の待ち時間を短くする
- 使うモデルを最新の Sonnet（`claude-sonnet-5-5`）にする

## 現状

- 画面 → GAS → Claude API の順に呼び、生成が全部終わってから一括で画面に返す。
- 既定モデルは `claude-sonnet-4-5`（思考なし）。出力上限は分析768・プラン1,024トークン。
- 画面は AI の文章をそのまま表示する（Markdown として描画しない）。テスト時の出力には `#` 見出しや `**太字**` が混ざり、記号がそのまま見えていた。文字数も指定（分析200〜300字）を超えていた。
- 待ち時間の内訳（GAS の起動・安全確認・生成）は実測していない。

## 方針

- Sonnet 5.5 は何も指定しないと「思考」してから答えるため、4.5 より遅くなる。短いコーチ文には思考は要らないので、`thinking: {type: "between_tools"}`（Sonnet 5.5 で思考を止める指定）を付ける。この指定は他のモデルではエラーになるため、Sonnet 5.5 のときだけ付ける。
- 生成の速さは出力の長さにほぼ比例する。プロンプトで「記号なし・指定字数を守る」を明示して出力を短くする。
- 「常に最新の Sonnet」は自動では追わない。最新版を指す仕組み（エイリアス）はなく、Sonnet は世代ごとに API 仕様が変わってきたため、自動で切り替わると突然エラーになりうる。コードの既定を最新 Sonnet にし、新しい Sonnet が出たら評価してから更新する運用にする。

## 段階

| 段階 | 内容 | 費用・本番への影響 |
|---|---|---|
| 1 | 既定モデルを `claude-sonnet-5-5` に。Sonnet 5.5 のときだけ思考オフを送る | なし（手元のコードのみ） |
| 2 | 分析・プランのプロンプトに「Markdown記号を使わない・字数を守る」を追加 | なし |
| 3 | テスト・docs（AI-SECURITY.md のモデル節、運用ルール）・評価スクリプトの費用表示を更新 | なし |
| 4 | `npm run check` と評価のリクエスト確認（`eval/run.mjs --dry-run`）で検証し、コミット | なし |
| 5 | 実際の API で速さと文章の質を比較（本番版 vs 新版） | API費用 約$0.5以内。APIキーが必要。ユーザーの了承後 |
| 6 | GAS へ反映（docs/RELEASE.md の手順） | 本番操作。ユーザーの指示後 |

## 対象外

- 文章を生成しながら少しずつ表示する方式（ストリーミング）。GAS は途中経過を返せないため、Cloudflare Worker 側で Claude を呼ぶ形への作り直しが要る。APIキーの置き場所・利用上限の管理も移すことになるため、別案件とする。
