## 完了条件と根拠

| 条件 | 実装と確認 |
| --- | --- |
| 保存・AI通信を待ち続けない | `transport.js`に通信処理を集約。保存30秒、AI45秒。応答本文の読み取り中も上限に含む。AbortSignalを無視する模擬通信でも期限・取消で呼び出し側を解放する自動テストが成功 |
| 保存の再試行で二重登録しない | 同一内容・送信IDを保持。保存結果が不明な間は氏名・メール・同意を固定し「保存を再確認する」を表示。明示的な入力拒否時だけ修正を許可。応答喪失の自動テストと実画面で重複通知なし |
| AI失敗と本文を分けて復旧する | 工程2のエラー／本文分離・安全確認後の再試行を保持。HTTP429・500、不正JSON、本文の型不正を自動検証。実画面でも429から分析、不正JSON／500からプランへ復旧 |
| 外部応答で画面を壊さない | statusを含む応答形式を検証。サーバーの任意メッセージは表示せず、既知のコードをアプリ側の短い案内に変換。未知コードで保存結果の不明状態を解除しない |
| リセットで古い結果を反映しない | 工程2の世代判定を保持し、保存通信にも取消を接続。取消後の保存再確認で同じIDを保つ自動テスト、遅延した旧プランが次の診断に混入しない実画面確認が成功 |
| 入力不備を送信前にも拒否する | form送信、関連付けたlabel、required／type=email／maxLengthと明示検証。氏名200文字・制御文字禁止、メール254文字・形式検証。無効メールで実際の保存リクエスト0件を確認。Enter送信も確認 |
| 安全確認の読み込み失敗から復旧する | SDK読み込み15秒、エラー・時間切れのトークン破棄、再読み込み、破棄失敗時の局所清掃。自動テストでタイムアウト後の再読込、実画面でSDK取得失敗・render例外・チャレンジ時間切れを確認 |
| グラフが壊れても結果を読める | 独立した`ScoreChart`、Error Boundaryと局所再表示、数値表を追加。Chartの初期化失敗を注入しても8項目を確認でき、再表示で復旧。24項目の数値表も確認 |
| AI更新でグラフを再生成しない | 工程2の安定したカテゴリ配列・回答を依存値とするEffectを`Radar`へ移動。AI stateを依存値にしない。離脱時はdestroyし、初期化途中で例外が出た場合の登録済みChartも破棄する |

アプリ最上位にもError Boundaryを置いた。Chartと安全確認の局所障害ではApp側の回答を保持する。アプリ全体の想定外エラーは再読み込みを案内する最終手段であり、その場合の入力喪失・保存結果不明の可能性を表示する。すべての例外から無損失で復旧できると保証するものではない。[React公式のError Boundary](https://react.dev/reference/react/Component#catching-rendering-errors-with-an-error-boundary)

## 工程2で残っていた不足への追加改善

- Claudeへ送る分析プロンプトから氏名を除去。送信するのは固定の設問と検証済みスコア。メールも送らない。GASの登録・通知と利用証明の氏名照合は維持する。両AIアクションの実際の模擬送信bodyを検査した。
- キャッシュサービス取得・読み取りが失敗しても、保存証明・人間確認・永続的な利用枠の検証後にだけ生成を許可する。キャッシュ障害で利用上限が初期化されないことを確認した。
- 分析とプランが両方表示された後は、操作のない安全確認を非表示にする。

Turnstileの設定・callbackは[Cloudflare公式仕様](https://developers.cloudflare.com/turnstile/get-started/client-side-rendering/widget-configurations/)を参照。実ウィジェットの通過確認はこの工程には含まない。
